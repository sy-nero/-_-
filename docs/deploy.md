# העלאת האפליקציה לענן

למה בכלל: **מעקב הפתיחות עובד רק מכתובת שנגישה מהאינטרנט.** הפיקסל נטען
מתוכנת המייל של הנמען, ותוכנת המייל שלו לא יכולה להגיע ל-localhost שבמחשב
שלך. בנוסף, אפליקציה בענן זמינה מכל מקום ולא רק כשהמחשב פתוח.

## לפני הכול: סיסמה

האפליקציה מציגה לידים ושולחת מיילים בשם החברה. בענן היא חשופה לכל מי שיש
לו את הכתובת, ולכן **חובה** להגדיר `APP_PASSWORD`. בלי המשתנה הזה
האפליקציה עובדת בלי כניסה — מצב שמתאים רק להרצה מקומית.

הפיקסל (`/px/<id>.gif`) ובדיקת הבריאות (`/health`) נשארים ציבוריים
בכוונה: תוכנת המייל של הנמען לא יכולה להתחבר עם סיסמה.

## Render — המסלול הפשוט

1. להיכנס ל-https://render.com ולהתחבר עם GitHub.
2. **New → Blueprint**, לבחור את הריפו ואת הענף. Render יקרא את
   `render.yaml` שכבר נמצא בפרויקט ויציע שירות בשם `sy-nero-campaigns`.
3. למלא את המשתנים שמסומנים `sync: false`:

   | משתנה | מה למלא |
   |-------|---------|
   | `APP_PASSWORD` | סיסמה שתבחרי לכניסה לאפליקציה |
   | `SMTP_HOST` | `smtp.gmail.com` |
   | `AGENT_FROM_EMAIL` | הכתובת שממנה יוצאים המיילים |
   | `AGENT_SMTP_USER` | חשבון הג׳ימייל שמתחבר |
   | `AGENT_SMTP_PASSWORD` | סיסמת אפליקציה של אותו חשבון |
   | `GOOGLE_MAPS_API_KEY` | רק אם רוצים לסרוק מהשרת |
   | `TRACKING_BASE_URL` | ממלאים אחרי הפריסה — ראו שלב 5 |

4. **Create** וממתינים לבנייה הראשונה.
5. Render ייתן כתובת בסגנון `https://sy-nero-campaigns.onrender.com`.
   מכניסים אותה ל-`TRACKING_BASE_URL` ושומרים — השירות יופעל מחדש,
   ומעכשיו כל מייל יוצא עם פיקסל מדידה.

### תוכנית בתשלום — לא גחמה

`render.yaml` מבקש **דיסק קבוע** (`/var/data`, 1GB). בלעדיו כל הנתונים —
לידים, קמפיינים, מדידות — נמחקים בכל פריסה מחדש ובכל הפעלה מחדש של
השירות. דיסק קבוע דורש תוכנית `starter` (כ-7 דולר לחודש). התוכנית החינמית
גם מרדימה את השירות אחרי חוסר פעילות, ואז פיקסל שנטען בזמן שהשירות ישן
פשוט לא נספר.

## העברת הנתונים מהמחשב לענן

הלידים שכבר אספת יושבים בקבצים במחשב. באפליקציה יש עמוד **גיבוי**:

1. במחשב: `python webapp/app.py`, ואז עמוד "גיבוי" ← **הורדת גיבוי מלא**
   (קובץ zip).
2. באפליקציה שבענן: אותו עמוד ← **שחזור** ← להעלות את ה-zip.

אותו מנגנון עובד גם בכיוון ההפוך ולגיבוי שוטף.

## דומיין משלך

ב-Render: Settings → Custom Domain, למשל `track.sy-nero.com`, ואז להוסיף
רשומת CNAME אצל ספק הדומיין. אחרי שהדומיין פעיל — לעדכן את
`TRACKING_BASE_URL` לכתובת החדשה. כתובת בדומיין שלך נראית טוב יותר
בקוד המקור של המייל מאשר `onrender.com`.

## חלופות

`Dockerfile` בפרויקט מאפשר פריסה לכל שירות קונטיינרים (Cloud Run, Fly.io,
Railway). בכולם חשוב אותו דבר: **volume קבוע** שממופה ל-`DATA_DIR`,
ומשתני הסביבה שלמעלה.

## סריקה — נשארת במחשב

`scan` ו-`enrich` הן פעולות ארוכות שמושכות מ-Google Places ומאתרים. הן
ממשיכות לרוץ מהמחשב שלך; אחר כך מעלים את הנתונים לענן דרך עמוד הגיבוי.
אפשר להריץ אותן גם על השרת (Render Shell), אבל זה דורש שהמפתח יהיה
מוגדר שם ושהתוכנית תאפשר גישת מעטפת.

## אחסון חינמי שעומד בפריסה מחדש: Cloudflare D1

בתוכנית החינמית של Render מערכת הקבצים נמחקת בכל פריסה, ולכן קובצי
SQLite לא שורדים. הפתרון בלי לשלם: **Cloudflare D1** — SQLite מנוהלת.
אותו דיאלקט SQL בדיוק, ולכן הקוד עובד מולה בלי שינוי.

### מה להגדיר

1. ב-Cloudflare: **Storage & databases → D1 SQLite Database → Create**
   (או להשתמש במסד שכבר יצרת). ב-**Overview** של המסד מופיע ה-
   **Database ID**, ובעמוד החשבון מופיע ה-**Account ID**.
2. **My Profile → API Tokens → Create Token**, עם הרשאת
   `Account → D1 → Edit`. הטוקן מוצג פעם אחת — להעתיק מיד.
3. ב-Render, Environment, שלושה משתנים:

   | Key | Value |
   |-----|-------|
   | `D1_ACCOUNT_ID` | ה-Account ID |
   | `D1_DATABASE_ID` | ה-Database ID |
   | `D1_API_TOKEN` | הטוקן |

זה הכול. כששלושתם מוגדרים המערכת עוברת ל-D1 אוטומטית, יוצרת את הטבלאות
בהרצה הראשונה, והנתונים שורדים פריסות והרדמות. אם המשתנים ריקים —
המערכת חוזרת לעבוד מול קבצים מקומיים, וכך פיתוח במחשב נשאר פשוט.

### מה כדאי לדעת

**מסד אחד לכל הקמפיינים.** ב-D1 אין קבצים נפרדים, ולכן שם הקמפיין נכנס
לשם הטבלה: `leads_agent`, `leads_crm` וכן הלאה. יומן השליחות עבר מקובץ
טקסט לטבלה `sent_emails` — כך ההגנה מפני שליחה כפולה שורדת גם היא.
קובצי `sent_*.txt` מהגרסה הקודמת ממשיכים להיקרא, כדי שאף אחד לא יקבל
מייל פעמיים.

**כל שאילתה היא קריאת רשת.** סריקה עושה שאילתה או שתיים לכל ליד, ולכן
היא איטית יותר מול D1 מאשר מול קובץ מקומי. בפועל זה נסבל — סריקה כבר
מוגבלת בהשהיות מול Google — אבל זה מורגש.

**שחזור.** ל-D1 יש Time Travel בלוח הבקרה של Cloudflare: אפשר לחזור
לנקודת זמן. עמוד הגיבוי באפליקציה נוגע רק לקבצים מקומיים.
